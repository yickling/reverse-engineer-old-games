# Prompt

Paste the block below to start or continue a study. Fill the brackets. One session does one task. The order is [procedure.md](procedure.md).

```
Read LLMs.md, procedure.md, and note-shape.md. Then read <game>/README.md if that folder exists.

Game folder: <game>
Task: <Start the study at the first open phase. | Do the open item "<title>" and nothing else.>

The program is the local copy. Read it. Leave it unchanged. A note cites an offset from a base the file records, or a file offset in the program as shipped. The note does not name the local copy.

The study is the play this program has. Read the gameplay loop and the presentation of art and sound assets. Name which picture, clip, or sample the loop asks for. Leave a sound driver, and any other platform or driver body, unread. Extract the gameplay mechanics and the algorithms that implement them. Write each algorithm as pseudocode that names the function, as LLMs.md requires. A description of the screen without that arithmetic is not the mechanic. When a rule is still a sentence, rewrite it as that block. The block is the record. A sentence may name the function and say what the player sees. It does not keep the arithmetic. Investigate the file formats used to store assets and how those assets are stored, including art, music, sound, 3D models, scripts, and animation, and any other kind a loader opens. For each kind this program stores, name the format, where the file sits, and the layout the loader reads. A kind it does not store is one sentence, not a guessed format. When the picture is 2D, ignore 3D models. When the picture is 3D, ignore 2D sprites. The index says which the picture is. Read tools/README.md before writing a program that opens a container or an asset. When that file already names it, use that program. When the walk is a container or a format another program can have, put the program in tools/, add a row there, and leave a short script in <game>/scripts/ that names this game's files and calls it. A script that only names this game's files stays in <game>/scripts/. Read each body the way LLMs.md describes for this container. The reader's output is not original source. Do not run the game. A phase this program has no system for is one sentence in the index, and the session goes on. Write each finding into the topic file before you finish. When the finding is something the player sees, say what they see in that same place. A chat reply is not a record. An address, file, or field you saw and did not read goes in <game>/gaps.md under that topic. Remove the row when the finding is written. Do not paste scenario prose. A file the archives do not hold stays absent.

Follow procedure.md. Stop when this task's done line is met. Then replace the coverage percentage in the game index, as LLMs.md describes, and state that percentage.
```
