# Startup and the outer loop

Part of the [FDPS notes](README.md). Decompiled functions are Ghidra output, not original source. Nothing here was checked by running the game.

Disassembly of `object 1 + 0x191f0` (frame `0x3c`), not a decompile. The functions it calls were decompiled. The outer loop is the session, not the battle. `object 1 + 0x1b870` keeps the map until the outcome dword is nonzero or the system menu returns nonzero, and only then does `object 1 + 0x191f0` look at that outcome. What each key does inside that visit is in [Turns](turns.md).

1. `object 1 + 0x321a8` opens `DISK.NO`. Failure prints `Can't found file 'Disk.No'` and `Please use install function.`, then `exit(1)`.
2. Opens `Disk.no` in `"rt"` and scans `%s` three times. The first two scans share one stack buffer. The third is stored at `object 2 + 0x43e8` and later used as a directory prefix.
3. Calls `object 1 + 0x2c3a6`. That asks whether a CD-ROM drive is present and reads the disc's track list, in [File formats](formats.md). It returns 0 when the drive count is 0, 2 when the disc-info status word is `0x810c`, and 1 otherwise. The following compare against 1 falls into an unconditional jump that skips the CD-ROM failure strings at `object 2 + 0x1c3c` and `object 2 + 0x1c64`. This copy never reaches those messages.
4. `object 1 + 0x20270(0x19)` starts the two sound devices (eight channels on the second) and passes `0x19` on to `object 1 + 0x20540`. That function stores the handle from `object 1 + 0x2df06` (`object 1 + 0x20520`). A handle of −1 prints the string at `object 2 + 0x1ea8`. It then calls `object 1 + 0x2e15a(handle, 0x19)` and `object 1 + 0x2e323(handle)`. `object 1 + 0x2df06` forwards the tick to `object 1 + 0x34cbe`. The log string names `AIL_register_timer`. `object 1 + 0x2e15a` forwards the handle and `0x19` to `object 1 + 0x34e50`. The log string names `AIL_set_timer_frequency`, so `0x19` is the frequency it requests. `object 1 + 0x2e323` forwards the handle to `object 1 + 0x34d78`. The log string names `AIL_start_timer`. Those three Miles bodies were not read. The wrappers share the log gate in [Pictures](pictures.md). When the register wrapper logs, it also calls `object 1 + 0x2f439`, which was not read. No function was created at `object 1 + 0x20520`. The bytes there increment `object 2 + 0x9d64` and call `object 1 + 0x32a68`, discarding the value. That call advances the seed in [Combat](combat.md). `object 1 + 0x19630` then loads the shared interface from `MISC.VFS` and `FIELD.VFS`: both palettes, the cursor, command window, shadow, status, message box, digits, selection bar, level-up picture, window, bars, `FDETXT.FON`, and `FDETXT00.TXT`. The font metrics, and `FDETXT00.TXT` kept at `object 2 + 0x43d0`, are in [Text](text.md). Mode 13h follows. `object 2 + 0x9cf0`, `object 2 + 0x9cdc`, quit byte `object 2 + 0x43eb`, and outcome dword `object 2 + 0x9da0` are cleared. `object 2 + 0x9d54` is set to `-1` just before the dead CD check; `object 1 + 0x20960` later stores the music track there.
5. `object 1 + 0x1a280` is the title. It returns only after a real menu choice. Its return value is ignored. The choice's writes are what matter.
6. While quit byte `object 2 + 0x43eb` is 0: call `object 1 + 0x1b870`, then switch on outcome `object 2 + 0x9da0`.
   - 0: nothing.
   - 1: `object 1 + 0x1a920` plays `GameOver.saf` over a copy of the screen and fades for `0x10` steps, then the title runs again.
   - 2: `call dword [object 2 + 0x304 + scenario*4]`, then `object 1 + 0x20f80`.
   - Outcome is then cleared, so a value written by the ending does not fire again on the next pass.
7. On quit: `object 1 + 0x19410` frees the interface, font, text, icon cache, unit array, and one triple of buffers per loaded section. `object 1 + 0x20330` is only `object 1 + 0x2d622`, the sound shutdown. `object 1 + 0x2c217` is the stop-audio request in [File formats](formats.md). The same function runs when music is stopped and at the start of each title cycle, so it is not exit-only. Mode 03h, then the string at `object 2 + 0x1c80` (`Thank you for playing Flame Dragon Plus!!`).

`object 1 + 0x1a280`, the title, decompiled:

- If `FDE.SAV` exists, its checksum matches, and the scenario byte at file `0x30c5` is not `0xff`, the first three menu-enable bytes are cleared. Otherwise they stay the dword at `object 1 + 0x191e0`, which is `00 02 02 00`. A row accepts Enter or Space only when its byte is 0, so a missing or empty save leaves the first and last rows choosable and the middle two refused.
- `Logo.saf` plays under `Dynasty.pal` until a key below `0x80` or the clip ends, between vertical-retrace waits.
- `FD%d` is filled with 1 or 2. `object 1 + 0x20cb0` shuts sound down, blanks the palette, and passes `{prefix}\fd.exe`, `{prefix}\FD1.Vid`, and `{prefix}\FD1.Aud` to CRT `object 1 + 0x3df59`. Inferred: that is an external intro, because the three paths are an executable plus a video and an audio file and the screen is cleared around the call. It was not confirmed by running it. Sound is then started again with `0x19`, and `object 1 + 0x20960(1)` requests track 1, which asks the drive for CD track 2, in [File formats](formats.md).
- The menu is `StBoard.cel` plus four rows of `StSel.cel`. Up and down move the row. A countdown of `0x5dc` ticks leaves the menu without taking a row; the logo then runs again and the intro number flips between 1 and 2.
- Row 0: scenario index 0, roster threshold 0, call the scenario opener, set `object 2 + 0x158` to 1.
- Row 1: `object 1 + 0x14460` draws `Load.cel` and, on confirm, copies one save slot (`0x312b + slot * 0xa28`, the same stride as the four `0xff` markers). Return `-1` stays on the menu. Any other return sets `object 2 + 0x131`, and return `1` calls the between-battle function below. The slot layout is in [Save](save.md).
- Row 2: `object 1 + 0x13df0` restores the battle at the front of `FDE.SAV` (map block, roster, unit array, camera and cursor already multiplied back by 24, scenario index) and plays `PlyPhase.saf`. The map loop then runs directly.
- Row 3: sets the quit byte.

`object 1 + 0x1b870` reads the key once per pass. A new key is handled immediately. The same key is ignored for movement on repeats 1 through 5, then repeats. Arrows move the cursor and play `Beep.wav`. Confirm either moves the unit, opens the command on an ineligible unit, or, with nobody under the cursor, calls the system menu. That menu's return value is the loop's leave flag, and its quit path returns 1 after setting the quit byte. `object 1 + 0x209c0` on each new tick counts to `0x4b` and, when the track is set and a status call is nonzero, starts that track again. The pass redraws through `object 1 + 0x1bc40`. The loop returns when the outcome dword is nonzero, or when the system menu returned nonzero.

`object 1 + 0x20960(n)` stores `n` as the track. A cleared sound byte forces `-1`. `-1` calls `object 1 + 0x2c217`. Any other value calls `object 1 + 0x2c5cb(n + 1)` when sound is enabled. The number passed is the CD audio track, in [File formats](formats.md). The map's restart of the same value is why.

Outcome 2 is not the opener. `object 2 + 0x304` is the per-scenario ending, 30 pointers, from `object 1 + 0x2a180` for index 0 through `object 1 + 0x2b7f0` for index 29. Disassembly of those thirty bodies, not a decompile. Indexes 0 through 25, 27, and 28 each store their own index plus one into `object 2 + 0x9cf4` and return. Every path in those bodies stores that same next index. Index 26, at `object 1 + 0x2b660`, stores 27 only when `object 1 + 0x24290(0, 0xb3)` and `object 1 + 0x24290(3, 0xdc)` both return a pair index. It then removes those pairs with `object 1 + 0x15c90`, plays `WinGA26.dat`, calls `object 1 + 0x29be0`, and stores 27. If either search returns −1, it plays `Win26.dat`, calls `object 1 + 0xba10`, sets quit byte `object 2 + 0x43eb`, and leaves the index at 26. Index 29 plays `Win29.dat`, stores 1 into `object 2 + 0x158` and `object 2 + 0x159`, calls `object 1 + 0xba10`, calls `object 1 + 0x2d0e0(0x7530)`, plays `GoodEnd.dat`, sets the quit byte, and stores no next index. `object 1 + 0x2d0e0` jumps to `object 1 + 0x33a20`, which waits on DOS time function `0x2c`. The count is the argument times the dword at `object 2 + 0x9ea8`, plus `0x1f4`, divided by `0x3e8`. `object 1 + 0x24290(slot, id)` returns the pair index of that id on that roster slot, or −1. `object 1 + 0xba10` requests track 1 and plays one reel for every roster slot, then one more. The text id is `0x20` plus the slot when the scenario index is `0x1d`, and `0x19` plus the slot otherwise. On index `0x1a`, slot 3 is skipped: the loop stores 4 before the body, and the loop's own step then advances from 4 to 5. The extra pass uses character id `0x0c`. Each pass loads `Stand%03d.saf`, `Act%03d.saf`, and `Back%02d.saf`. The stand and the act use the roster character id, from `object 1 + 0x13920`. The backdrop number is the slot times 3. The frames are in [Pictures](pictures.md). It then reloads `Mer1.tmp` and `Mer2.tmp`, restores the map palette, and calls `object 1 + 0x20cb0` with the three characters at `object 2 + 0x1768`.

Before the store, the ending plays one icon script through `object 1 + 0x11620`. Indexes 0 through 16, 18 through 25, 27, and 28 play `Win%02d.dat`. Index 17 plays `Win17-1.dat` when the check below passes, and `Win17.dat` otherwise. `object 1 + 0x29be0`, which opens `Relive.cel`, runs after the script and before the store. Index 26's quit path and index 29 do not call it. `object 1 + 0x13950` is called by every ending except index 26. For each battle slot it finds the roster record whose byte `+8` matches. Character id 0 is skipped when that slot is already gone. Otherwise it copies the 80-byte battle record over the roster record, clears the six count bytes at `+0x22`, and keeps only bit 0 of `+5`. When that bit is clear it copies `+0x42` back into `+0x40`. It always copies `+0x46` into `+0x44`. A byte `+0x3c` above `0x63` is stored as 0. It then calls `object 1 + 0x13a90` on that roster index. Endings other than 0, 1, 14, and 18 call `object 1 + 0x29b80` first. That function stores 0 into `+0x40` of every unit whose side is 0, then calls `object 1 + 0xd690`, the death spin in [Combat](combat.md). Index 0 instead calls `object 1 + 0x18280(0, 0)`, which sets learned-id bit 0 on slot 0.

A few endings change a unit or a script name and still store the same next index. Index 14, when byte `object 2 + 0x40e8` is nonzero, clears `+5` on slots 0 through 8 and stores 0 into `+0x34` of slot `0x34`. Index 17 searches slot 0 for item `0xa9`. When that pair exists and units 0 through 8 each have byte `+7` equal to byte `+8`, it removes the pair and gives id `0xdb` to slot 0, then plays `Win17-1.dat`. Otherwise it plays `Win17.dat`. Either way the next index is 18. Indexes 18 and 23, when byte `object 2 + 0x40e9` is nonzero, clear `+5` and copy both maximum pools into the current pools for every unit whose character id is at most `0xb`. Index 22 sets `+5` on each side-1 unit from slot `0xb` up to the slot count. Index 25, when slot 0 has no item `0xa2` and `object 1 + 0x15210(0)` is not 8, shows scenario string `0x18` and gives id `0x62` to slot 0. Indexes 18 and 23 store 1 into `object 2 + 0x40e9` at the end of that after-action branch, at `object 1 + 0x2ae09` and `object 1 + 0x2b35e`. Step handlers also store both bytes, in [Scenario files](scenario.md). Handler 13 increments `object 2 + 0x40e9`. Handler 21, at `object 1 + 0x278e0`, stores 1 into `object 2 + 0x40e8`, and no row or pair of the map files selects it.

`object 1 + 0x20f80` then runs the between-battle step, and it reads the index the ending just stored. If the quit byte is already set it returns at once, without the village and without the opener. The session then clears the outcome and the loop leaves. For scenario indexes other than `0x10`, `0x11`, `0x15`, `0x16`, and anything at or above `0x1a`, it draws `Village.cel` with `ShopWin.Cel` and stays in a menu until the selection returns to 0 or quit is set. Arrival at 16, 17, 21, 22, or 26 through 29 is the skipped set. The five nonzero selections call `object 1 + 0x25a30`, `object 1 + 0x25810`, `object 1 + 0x255d0`, `object 1 + 0x25d40`, and `object 1 + 0x25f80`. The corners are in [Turns](turns.md). Indexes in the skipped set call `object 1 + 0x20960(-1)` and, unless `object 2 + 0x131` is set by the load row, `object 1 + 0x141b0` on a blank screen. That function writes one title slot of `FDE.SAV`, in [Save](save.md). Either way it saves `object 2 + 0x158`, stores 0, calls `(&`object 2 + 0x74`)[scenario]`, and writes the saved byte back. That table is the opener, also 30 pointers, beginning `object 1 + 0x10e60`, `object 1 + 0x10ec0`, `object 1 + 0x10f00`. Each one calls `object 1 + 0x12720` (the map load: outcome cleared, camera and cursor zeroed, turn counter set to 1), then `object 1 + 0x11620` on that scenario's icon script, then `object 1 + 0x10c30`, then `object 1 + 0x1d7e0`. `object 1 + 0x10c30` draws `Chapter.saf` under `Chapter.pal` and fades the palette sixteen steps down and back up. The icon script is in [Scenario files](scenario.md).

`object 1 + 0x13b90` is the only function that appends a roster character. The call sites, and no other function, pass these ids: scenario 0 passes 0, 1 passes 6, 2 passes 4, 3 passes 1, 6 passes 3, 7 passes 2, 8 passes 8 and then 9, 10 passes 7, 14 passes 5, 18 passes 11, and 23 passes 10. The other indexes in 0 through 29 do not call it. What the append writes is in [Units](units.md). The battle copies that roster from the front, stopping at byte 1 of the map, so an id appended when the count already equals that byte is not placed. There is no screen in the functions read here that removes a roster record or refuses to drop one. `object 1 + 0x21930`, called from this village step, cycles which roster record is shown and leaves on confirm. It does not change the count.

Disassembly of all thirty openers, not a decompile. Each one is the four calls above, and `object 1 + 0x1d7e0` is passed a slot. Indexes 16, 21, and 22 pass 3. The other twenty-seven pass 0. Index 0 also writes `0xb` to unit 2's `+0x25` and 100 to its `+0x40` before that call. Index 14 calls `object 1 + 0x1d8e0` first, which clears bit `0x80` of byte `+5` on every slot. Index 23 appends after the map load. The other appends run before it, so an id appended by index 23 is not placed in that battle. How a scenario's files are read is in [Scenario files](scenario.md).
